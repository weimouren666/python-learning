# Git 最小生存指南 —— 写给学习仓库的主人

> 目标：了解 git 是什么、会看懂 `git log` 学习日志；日常推送由 AI 老师从云端沙箱自动完成（2026-11-17 起），你只需在需要时 clone/pull。
> 只学必须的，不学暂时用不上的。详见第 6 节现行推送路线。

## 0. 为什么这事值得（30 秒）

- git 会给每一次提交拍一张"快照"，一年后 `git log` 就是你 14 周的完整成长日志
- 这是你们专业大二大三的必修工具（数据结构、大数据框架全靠它协作），现在用最安全的方式练手
- 简历上"用 git 管理学习代码 + commit 历史清晰"是真实加分项

## 1. 一次性安装与配置（10 分钟，只做一次）

**装 Git**：去 [git-scm.com](https://git-scm.com/download/win) 下载 Windows 版，安装时一路默认（默认选项已经很好）。

**配置身份**（告诉 GitHub 是谁在提交）。打开 **Git Bash**（装完 git 开始菜单里就有），逐行执行：

```bash
git config --global user.name "你的名字(拼音或网名)"
git config --global user.email "你注册GitHub用的邮箱"
```

⚠️ 邮箱必须和你 GitHub 账号的邮箱一致，否则贡献统计不显示在你头像下。

## 2. 首次把文件放进仓库（5 分钟，只做一次）

最省事的方式是 **clone（克隆）**—— 把 GitHub 上的空仓库拉到本地：

```bash
cd ~/Desktop                # 你想放代码的地方
git clone https://github.com/你的用户名/仓库名.git
cd 仓库名                   # 进入仓库目录
```

然后把整个学习档案复制进这个仓库文件夹。**现行目录结构（2026-11-17 重排，类型+周次混合）**：

```
python-learning/
├── 01-课程讲义/       # 15 份 HTML，按第1—6周分子目录
├── 02-作业代码/       # 按周次分子目录（bmi/shizhan1、词频升级、函数练习…）
├── 03-教材实验/       # 《大数据导论》联动实验
├── 04-参考资料/       # Git指南 / pandas介绍 / 术语手册 / 讲义模板
├── 05-历史归档/       # 旧版 zip
├── README.md          # 总索引
├── Python学习计划.md
└── 学习状态.md
```

第 6 周之后按同一规则加周次子目录即可。

## 3. 每周三板斧（课后 5 分钟，重复使用）

在仓库目录里打开 Git Bash（或右键 → Open Git Bash here），按顺序：

```bash
git add .                                       # ① 把所有新文件/改动放进"待提交区"
git commit -m "第2周：分支与循环 + 猜数字游戏"     # ② 拍快照，写一句说明
git push                                        # ③ 推送到 GitHub
```

第一次 push 会弹出 GitHub 登录窗口（浏览器授权），登录一次以后就不用了。

**记住这个节奏：改了东西 → add → commit → push。就这么简单。**

## 4. commit message 怎么写（这是你的学习日志）

公式：**第 N 周：主题 + 这次做了什么**

```bash
git commit -m "第1周：变量与数据类型，完成BMI计算器作业"      # ✅ 好
git commit -m "第1周实战：个人信息卡片生成器，修复缩进问题"    # ✅ 好
git commit -m "update"                                     # ❌ 半年后你自己都不知道干了啥
```

## 5. 常见事故与自救

| 状况 | 处理 |
|---|---|
| 忘了这次改了啥 | `git status` —— 随时敲，永远无害 |
| push 被拒绝（rejected） | 先 `git pull` 把远端拉下来，再 `git push` |
| commit 写错字了 | 还没 push 的话：`git commit --amend -m "新消息"` |
| 想看完整历史 | `git log --oneline` |
| 什么都不想记了 | 就记三板斧，其他的遇到再说 |

## 6. 推送路线（2026-11-17 改：沙箱云端推送，本地三板斧作备用）

> 路线变更史：11-12 曾定"本地推送、凭据不出电脑"；**11-17 学生改为云端沙箱推送**（理由：本地文件会丢、云端不会忘、不想每节课手动同步）。仓库 `https://github.com/weimouren666/python-learning`，默认分支 `main`。

**现行链路（沙箱即权威源，每节课 AI 直接提交）**：

```
沙箱 AI 老师（每节课生成讲义 / 作业 / 更新状态）
   ↓ 按类型+周次结构归档到对应目录
   ↓ 沙箱用 fine-grained token 通过 GitHub API 提交（详见下方）
GitHub（云端，不会忘、跨设备可见）
   ↓ 你在任何电脑 clone / pull 即得到最新版
你本地电脑（只读或偶尔提交都行）
```

**注意**：`git push` 从沙箱走不通（github.com:443 超时 136 秒），**必须用 GitHub Contents API 逐文件提交**（api.github.com 0.26 秒可达）。这条路由 AI 老师执行，你不用管。

**安全底线（云端方案下依然成立）**

- ✅ 用的 token 是 **fine-grained**：只授权 `weimouren666/python-learning` 一个仓库、只给 **Contents: Read and write** 一项权限、90 天过期、随时在 GitHub 设置页撤销。
- ✅ 仓库地址、分支名、目录结构这类**公开信息**可以随便发，那不是秘密。
- ❌ 不需要、也不要给我 classic token、账号密码、SSH 私钥——fine-grained token 的最小权限已经够用，多给一样都是多余风险。
- ✅ 万一哪天云端方案不用了，第 3 节的本地三板斧立刻能接上（目录结构一致，直接 clone 就能推）。

**这个 token 能做到什么、不能做什么**：能读写这一个仓库的文件、能提交；**不能**删仓库、改设置、碰其他仓库、访问你的账号信息。泄露的最大损失就是这一个学习仓库的内容（本来就是公开仓库）。
